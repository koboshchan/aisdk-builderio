Live testing uncovered two defects. Session ids alone did not continue native completion history, so later agent steps could call seed repeatedly. The fix sends the previous done event's cgen nextUrl in the next request body url, matching the official CLI. Internal compact:true done events also incorrectly terminated the SDK stream as a successful empty answer. They are now skipped until a real completion; compaction-only responses fail rather than claiming success.

Early diagnostic attempts failed: a maxOutputTokens=300 run returned only internal compactions and an empty answer; subsequent attempts exposed the repeated-seed problem. No undocumented bypass was used. The successful live tests omit an output cap and ask for short answers. The official schema describes maxTokens as output tokens, so that mapping is retained; tiny caps producing server compaction remain an upstream behavior rather than being relabeled as a context-budget API.
